# AxiomGuard v0.5.0

Release date: 2026-08-25

AxiomGuard 0.5.0 focuses on outbound-request safety, package integrity, and release reliability.

## Highlights

- Added `safeFetch()` with URL and DNS validation before the initial request and every followed redirect.
- Strips authorization and cookie credentials when a redirect crosses origins.
- Rejects caller-controlled transport/framing headers and fails closed when a redirect would require unsafe request-body replay.
- Added bounded redirect depth and a total redirect-chain timeout.
- Added `createRateLimitHeaders()` for current IETF draft fields plus compatibility headers and `Retry-After`.
- Added an import smoke test for every documented package subpath.
- Added scanner baselines, deterministic non-secret fingerprints, GitHub annotations, and SARIF correlation in the 0.4 line now included in this release candidate.
- Kept the SDK at zero runtime npm dependencies.

## Security boundaries

`safeFetch()` is an application-level guardrail, not a replacement for network egress controls. DNS is validated before each hop, but the underlying HTTP transport performs its own connection-time resolution, so DNS rebinding and time-of-check/time-of-use risk cannot be eliminated by a URL helper alone.

The secret scanner reports rule, file, line, and deterministic non-secret fingerprints. It does not include matched credential values in normal output, GitHub annotations, baselines, or SARIF.

- automated tests
- Node.js 24 coverage run
