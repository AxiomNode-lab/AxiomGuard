# AxiomGuard 0.6.1

AxiomGuard 0.6.1 is the first corrected public npmjs distribution for the 0.6 line.

## Highlights

- Browser request protection built from Fetch Metadata with exact-Origin fallback for unsafe requests.
- Bounded idempotency primitives plus atomic node-redis and ioredis adapters.
- Meta/WhatsApp and Slack signed-request verification alongside existing GitHub and Stripe helpers.
- Hardened SSRF-oriented URL/fetch checks, replay protection, redaction, CSRF, rate limiting and environment validation from the 0.5 hardening line.
- Express 5, Fastify 5 and Hono 4 integration coverage.
- Secret scanner CLI with text, JSON and SARIF output.
- Zero runtime npm dependencies.

## 0.6.1 packaging correction

GitHub Packages 0.6.0 was published successfully as a library package, but npm 11 normalized the package metadata and removed the CLI mapping because the `bin` target used a form npm considered invalid. Registry versions are immutable, so the corrected distribution is 0.6.1 rather than a divergent republish of 0.6.0.

0.6.1 uses the normalized `dist/cli.js` bin target and the clean-room package test now verifies both the installed manifest and the `node_modules/.bin/axiomguard` shim.

## Public installation

The primary public installation path is npmjs:

```bash
npm install @axiomnode-lab/guard
```

The exact 0.6.1 package was manually published to npmjs with public access, read back with `npm view`, and installed from `registry.npmjs.org` after the full repository qualification had already passed.

GitHub Packages remains an additional distribution channel and requires GitHub Packages authentication for npm clients.

## Qualification

The release source passed:

- Node.js 20, 22 and 24 CI
- TypeScript type checking
- 63 unit/regression tests
- clean-room tarball install and package export checks
- installed CLI shim execution
- package dry-run and self secret scan
- real Express/Fastify/Hono integration tests
- real node-redis/ioredis integration tests
- non-root/read-only container smoke tests
- GitHub Action and SARIF smoke tests
- repository CodeQL default setup

## Supply chain

The GHCR workflow is configured to emit SBOM and `mode=max` provenance for published container builds. npmjs automation is prepared for npm Trusted Publishing/OIDC and should be enabled after the package's Trusted Publisher configuration is completed on npmjs.

## Upgrade note

Consumers of GitHub Packages 0.6.0 that only use library imports are not known to require a code-level migration, but CLI users should move to 0.6.1. New consumers should use 0.6.1 or later.
